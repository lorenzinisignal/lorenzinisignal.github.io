Figma에서 variable2json 플러그인으로 내보낸 디자인 시스템 토큰을 Bootstrap과 Tailwind에 적용하는 방법을 검토했습니다. 회사 개발은 Vue와 React로 하지만, 디자이너 입장에서는 Bootstrap이나 Tailwind 클래스로 화면을 직접 구성하는 편이 더 간편합니다. 그래서 토큰을 적용한 라이브러리를 각각 만들어 두고, 디자인한 화면을 웹 화면으로 옮기는 방식 중 가장 편한 것을 고르는 것이 목표입니다.

조건은 이렇게 정했습니다.

- 한 프로젝트에는 두 라이브러리 중 하나만 씁니다.
- 두 라이브러리 모두 최신 버전 기준입니다 (Bootstrap 5.3.9, Tailwind v4.3).
- 다크 모드는 이번 범위에서 뺍니다.
- 보안상 Figma 연동 도구(MCP)를 쓸 수 없어서, JSON을 내보내 저장소에 커밋하는 흐름으로 갑니다.

## 토큰을 바로 넣지 말고 한 번 정리하기

내보낸 JSON을 라이브러리 설정에 직접 옮기기보다, 한 번 정리한 뒤 두 라이브러리용 결과물을 함께 생성하는 구조가 맞습니다.

```
토큰 JSON (Figma 원본, 저장소에 커밋)
  → normalize 스크립트 (이름 정리, 테스트용 토큰 제외, alias 해석, 단위 변환)
  → 생성 스크립트 (Style Dictionary 또는 직접 만든 스크립트)
      ├─ tokens.css     : CSS 변수 (실제 값은 여기 한 곳에만)
      ├─ _tokens.scss   : Bootstrap용 Sass 변수
      └─ theme.css      : Tailwind v4 @theme
```

variable2json 형식은 W3C 표준 토큰 형식(DTCG)이 아니어서 변환 스크립트가 필요합니다. alias가 컬렉션을 넘나들고 여러 단계로 이어지는 것도 풀어야 합니다.

## 토큰 파일에서 발견한 문제

파일을 끝까지 읽어 보니 Figma에서 먼저 고쳐야 할 것들이 있었습니다.

- **다크 모드 미완성**: 다크 모드 값이 일부 색 계열에서 모두 흰색이거나 light와 똑같았고, radius가 전부 0이었습니다. 다크 전환을 semantic 토큰이 아니라 primitive 팔레트에서 처리하고 있어서, 코드에서 `white`가 검정이 되는 구조이기도 했습니다.
- **명암비 미달**: warning 버튼의 흰 글자가 1.49:1, 경고 텍스트가 2.03:1로 WCAG AA 기준(4.5:1)에 크게 못 미쳤습니다. brand 버튼 흰 글자도 3.48:1이었습니다.
- **이름 문제**: `orange/010`처럼 오타로 보이는 단계, 대문자가 섞인 이름, 쉼표와 공백이 들어간 이름이 있었습니다.
- **테스트용 토큰 혼입**: 가이드선 색, 문자열 테스트 값 같은 작업용 변수가 섞여 있었습니다.

## 라이브러리가 요구하는데 토큰에 없는 것

Bootstrap과 Tailwind가 정의하는 항목을 토큰과 하나씩 대조했더니 52개 항목 중 15개가 우선순위 '높음'이었습니다. 묶어 보면 다섯 가지입니다.

| 묶음 | 빠진 것 |
|---|---|
| 상태 색상 | success 색, 상태별 연한 배경·테두리·강조 글자 색, 폼 검증 색 |
| 포커스 표시 | 포커스 링, 포커스 테두리 두께, 포커스 그림자 |
| 크기 | 버튼·입력창 높이, 테두리 두께, 크기별 안쪽 여백 짝 |
| 레이아웃 | 브레이크포인트, 컨테이너 최대 폭 |
| 글꼴 기본값 | 글꼴 패밀리 토큰, 본문 기준 크기, 기본 팔레트 처리 방식 |

디자인 툴에서는 컴포넌트를 그리면 끝이지만, 라이브러리는 "기본값"과 "상태"를 요구한다는 차이가 잘 드러났습니다.

## 단위 정하기

| 대상 | 단위 | 이유 |
|---|---|---|
| 글자 크기, 간격, 모서리 반경 | rem (1rem = 16px) | 두 라이브러리 모두 rem 기반이고, 브라우저 글자 크기 설정을 따라가 접근성에 맞습니다. |
| 줄 높이 | 단위 없는 비율 | 글자 크기를 따라갑니다. |
| 자간 | em | Tailwind 방식과 같습니다. |
| 테두리 두께, 그림자 | px | 1px 선은 확대해도 1px이 맞습니다. |
| 색상 | hex 그대로 | Figma 값과 1:1로 대조할 수 있습니다. |

본문 기준이 14px이어도 `html` 글자 크기는 바꾸지 않고 `body`에 `0.875rem`을 줍니다. 루트 크기를 바꾸면 라이브러리의 모든 값이 틀어집니다.

간격 클래스 이름은 라이브러리마다 다르게 정했습니다.

- **Tailwind**: 기본 규칙(1단위 = 4px)을 유지합니다. Figma 8px는 `p-2`입니다. 문서·예제·AI 도구가 모두 이 규칙을 전제로 하기 때문입니다. `--spacing-md` 같은 semantic 이름을 등록하면 `max-w-md`, `w-md` 값까지 그 변수로 바뀝니다. 직접 빌드해서 확인했고, 그래서 피했습니다.
- **Bootstrap**: 기본 간격이 6단계뿐이라 토큰 14단계를 담을 수 없습니다. 키를 px 숫자로 바꿔 `p-8`이 8px가 되게 합니다.

## 라이브러리별로 걸리는 점

**Bootstrap**
- Sass 색 함수는 고정 hex 값이 필요해서 `$primary`에 CSS 변수를 넣을 수 없습니다.
- 버튼 hover 색을 자동으로 계산하는데 토큰에는 hover 색이 따로 있어서 직접 지정해야 합니다.
- 비활성 상태가 색으로 정의돼 있으니 기본 비활성 투명도(0.65)를 꺼야 합니다.
- 그리드 gutter가 두 종류인데 Bootstrap 변수는 하나라 컨테이너를 나눠야 합니다.

**Tailwind**
- 토큰의 radius 이름(xs~xl)이 Tailwind 기본과 같은데 값이 달라서, 덮어쓰면 외부 컴포넌트 모양이 바뀝니다.
- 색상 계열 이름(gray, red, blue…)도 같지만 단계가 다릅니다. 기본 팔레트를 지우고 토큰만 쓸지 정해야 합니다.
- 색상을 `--color-*` 하나에만 넣으면 `bg-bg-surface-primary`처럼 접두어가 겹칩니다. 속성별 네임스페이스(`--background-color-*`, `--text-color-*`, `--border-color-*`)에 나눠 넣으면 `bg-surface-primary`, `text-primary`처럼 깔끔해집니다.

## 디자이너가 화면을 만드는 방식: 무엇을 고를까

| 기준 | Bootstrap | Tailwind + 컴포넌트 클래스 |
|---|---|---|
| 디자이너 작성 난이도 | 쉬움 (`btn btn-brand`) | 컴포넌트 클래스를 주면 비슷하게 쉬움 |
| 모달·드롭다운 동작 | 기본 제공 | 따로 필요 |
| Vue/React로 이관 | 불리 (Bootstrap JS가 DOM을 직접 조작) | 유리 (클래스를 그대로 옮김) |
| 디자인 일관성 강제 | 중간 | 높음 |
| AI 도구로 화면 생성 | 좋음 | 매우 좋음 |

결론은 **Tailwind에 컴포넌트 클래스를 더한 방식**입니다. 목적이 "디자이너가 만든 화면을 Vue/React 개발로 넘기는 것"이라 이관 항목이 결정적이었습니다. 라이브러리가 토큰으로 `btn`, `btn-brand`, `input` 같은 클래스를 제공하면 디자이너는 짧은 클래스로 화면을 만들고, 배치는 `flex`, `grid-cols-12`, `gap-4`로 처리합니다. 개발자는 그 마크업을 옮긴 뒤 필요할 때 컴포넌트로 감싸면 됩니다.

작업 흐름은 이렇게 잡았습니다.

1. **라이브러리 저장소**: 토큰에서 만든 테마 CSS, 컴포넌트 CSS, 클래스 목록 문서
2. **디자이너용 템플릿 저장소**: Vite + HTML 페이지, `npm run dev`로 실시간 미리보기. Tailwind는 쓴 클래스만 빌드하므로 CDN 파일 하나로 배포하는 방식은 맞지 않습니다.
3. **AI 도구 활용**: 템플릿 저장소에 규칙 문서(쓸 클래스, 임의 색·px 금지)를 두고, 디자이너가 화면 캡처와 설명을 주면 페이지를 생성하게 합니다.

마지막으로, 두 라이브러리를 버튼·입력창·테이블·레이아웃만 최소로 만들고 같은 화면 1~2개를 직접 만들어 비교한 뒤 확정할 계획입니다.

## 정리

- 토큰 JSON을 라이브러리에 바로 넣지 말고, 정리 단계를 거쳐 여러 결과물을 생성합니다.
- 라이브러리가 요구하는 기본값과 상태 토큰(포커스, 검증, 높이, 브레이크포인트)을 디자인 단계에서 먼저 채웁니다.
- 단위는 크기 계열 rem, 선과 그림자 px, 줄 높이는 비율로 정합니다.
- 최종 목적지가 Vue/React라면 클래스를 그대로 옮길 수 있는 Tailwind 쪽이 이관 비용이 낮습니다.

## 수정 내역

글을 올린 뒤 Tailwind 라이브러리를 실제로 만들어 보면서 세 군데를 바로잡았습니다.

- Tailwind v4의 색상 네임스페이스가 하나뿐이라고 적었는데, 속성별 네임스페이스가 있습니다.
- 간격 토큰 단계 수를 15로 적었는데 14입니다.
- `--spacing-*` 이름 충돌은 전해 들은 사례가 아니라 직접 빌드해 확인한 내용으로 고쳤습니다.

처음에는 생성 도구로 Style Dictionary를 생각했지만, 출력이 Tailwind 하나일 때는 의존성 없는 스크립트로도 충분했습니다.
