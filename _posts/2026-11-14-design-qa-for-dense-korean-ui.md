[지난 글]({% post_url 2026-11-14-design-token-library-repo-structure %})에서 만든 토큰 라이브러리로 사내 업무 화면 예시를 만들었습니다. 헤더, 왼쪽 메뉴(LNB), 조회 조건(필터존), 결과 표가 있는 고밀도 화면입니다. 12px 글자에 표 한 행이 29px쯤 됩니다.

1440px 모니터에서 스크린샷을 보고 "이상 없음"으로 끝냈는데, 디자인 QA 요청을 두 번 받았습니다.

1. "줄바꿈으로 두 줄이 되어 영역을 벗어나거나, 값이 안 보이는 경우가 있어요."
2. (고친 뒤) "여전히 말줄임이 안 되고 컴포넌트 밖으로 나가거나 높이가 어긋나요."

두 번째 결과물이 기대한 산출물로 확정됐습니다. 무엇을 봤고, 왜 첫 번째에 놓쳤고, 무엇을 다시 점검했는지 정리합니다.

## 1차 QA: 숫자로 재기 시작

눈으로만 보면 1px 넘침이나 행마다 다른 높이는 잘 안 보입니다. 그래서 Playwright로 화면을 열고 숫자로 쟀습니다.

- 글자가 두 줄 이상인지
- 입력창 값과 안내 문구가 입력창보다 긴지 (canvas `measureText`로 글자 폭을 재서 비교)
- 자식 요소가 부모 밖으로 나가는지

처음 만든 줄바꿈 점검은 아이콘과 글자가 다른 높이에 있는 버튼을 "두 줄"로 세서 오탐이 많았습니다. 요소 단위가 아니라 **텍스트 노드 단위**로 세도록 고쳤습니다.

```js
const range = document.createRange();
range.selectNodeContents(textNode);
const rects = [...range.getClientRects()].sort((a, b) => a.top - b.top);
let lines = 1;
for (let i = 1; i < rects.length; i++) if (rects[i].top >= rects[i - 1].bottom - 1) lines++;
```

1024~1920px에서 찾은 문제는 이랬습니다.

| 문제 | 원인 | 처방 |
|---|---|---|
| 날짜 입력이 아이콘만 남거나 "10/15/20"처럼 잘림 | 필터존을 12컬럼 `col-span-3`으로 고정. 한 화면 폭에 맞춘 값 | 필드 최소 폭을 정하고 칸 수는 브라우저가 정하게 (`repeat(auto-fill, minmax(…, 1fr))`) |
| 표를 가로로 넘기면 기준 열이 사라짐 | 고정 열 없음 | 앞쪽 열 고정 |
| 고정 열 위로 세로선이 비침 | `border-collapse`에서는 표가 테두리를 셀 위에 그림 | `border-separate` + `border-spacing: 0` |
| 고정 열 사이 틈으로 글자가 비침 | `left` 값을 손으로 적음 | 실제 열 폭을 재서 넣음 |
| 긴 값의 전체를 볼 수 없음 | `truncate`만 있음 | `title`로 전체 값 |

7개 폭에서 0건. 끝났다고 생각했습니다.

## 1차에서 놓친 것

두 번째 지적을 받고 보니 점검에 구멍이 두 개 있었습니다.

**조건이 하나였습니다.** 1024px 이상, 100% 배율만 봤습니다. 그런데 화면은 앱의 미리보기 패널(좁은 폭)이나 브라우저 확대 상태로도 열립니다. 125% 확대에서 1366px 노트북은 CSS 폭이 1093px이 되고, 900px 창은 720px이 됩니다.

**항목이 좁았습니다.** "글자가 박스보다 넓은데 말줄임이 없음", "같은 줄 버튼 높이가 다름", "고정 높이보다 내용이 큼"은 아예 보지 않았습니다.

점검을 넓혀서 1차를 통과한 화면에 다시 돌리니, 360px에서 45건, 900px × 125%에서 28건이 나왔습니다.

## 2차 QA: 조건과 항목을 넓힘

| 축 | 값 |
|---|---|
| 화면 폭 | 320 ~ 1920px, 13개 |
| 글꼴 | 기본 / 넓은 글꼴(자간 +6%로 시스템 글꼴 대체를 흉내) / 확대 125% |
| 상태 | 접힌 조건 영역을 펼친 상태 |

| 항목 | 실패로 보는 경우 |
|---|---|
| 넘침 | 모든 요소에서 `scrollWidth > clientWidth` (스크롤 영역 제외) |
| 말줄임 | 잘렸는데 `…`이 없음, 또는 `…`인데 전체 값을 볼 방법이 없음 |
| 영역 벗어남 | 요소가 부모 박스 밖으로 1px 넘게 |
| 줄바꿈 | 버튼·배지·라벨·표 칸·제목·메뉴의 글자가 두 줄 |
| 높이 | 고정 높이 넘침, 같은 줄 컨트롤 높이 다름, 표 행 높이 제각각 |

13 × 3 = 39가지 조건을 모두 돕니다.

## 핵심 원인: 한글은 음절마다 줄이 바뀐다

가장 많이 나온 문제는 "업무 포털", "조회 결과", "2건 선택" 같은 짧은 글자가 **세로로 네 줄**이 되는 것이었습니다.

flex 항목의 최소 폭(`min-width: auto`)은 "가장 긴 줄바꿈 단위"입니다. 영어에서는 단어지만, 한글은 음절마다 줄을 바꿀 수 있어서 **한 글자**입니다. 그래서 공간이 조금만 모자라도 한 글자 폭까지 줄어듭니다. 영어 화면에서는 잘 드러나지 않는 문제입니다.

세로로 늘어난 글자는 부모 밖으로 나가고, 그 줄의 높이를 밀어냅니다. "컴포넌트 밖으로 나감"과 "높이 어긋남"은 같은 원인이었습니다.

처방은 글자의 성격에 따라 둘로 나눴습니다.

| 글자 | 처방 |
|---|---|
| 줄어들면 안 되는 글자 (라벨, 버튼, 배지, 제목) | `white-space: nowrap` |
| 줄어들어도 되는 글자 (메뉴명, 경로, 사용자명, 긴 값) | `min-width: 0` + 말줄임 + `title` |

```html
<span class="w-16 shrink-0 whitespace-nowrap">출고 창고</span>
<span class="min-w-0 truncate" title="거래처별 미수금·여신 한도 초과 현황">거래처별 미수금·여신 한도 초과 현황</span>
```

배지는 어떤 화면에서도 한 줄이어야 하므로 라이브러리 컴포넌트에 `white-space: nowrap`을 넣었습니다.

## 나머지 처방

| 문제 | 처방 |
|---|---|
| 좁은 화면에서 헤더가 넘침 | 덜 중요한 것부터 숨김: 주 메뉴 → 검색 → 사용자 이름. 검색창은 먼저 줄어들게 |
| 왼쪽 메뉴가 본문 폭을 빼앗음 | 1024px 미만에서는 기본으로 닫고, 열면 본문 위에 겹치게 |
| 2칸짜리 필드가 1칸 그리드에서 넘침 | 컨테이너 쿼리로 조건 영역이 충분히 넓을 때만 2칸 |
| 아주 좁은 화면에서 안내 문구가 잘림 | 필드를 `flex-wrap`으로. 좁으면 입력창이 라벨 아래로 |
| 도구 막대에서 버튼이 삐져나옴 | 고정 높이 → 최소 높이 + 버튼 묶음째 줄바꿈 |
| 창 높이가 낮으면 표가 거의 사라짐 | 본문 세로 스크롤 + 결과 영역 최소 높이 |

원칙으로 묶으면 세 가지입니다.

1. 글자는 줄바꿈하지 않고, **묶음**(필드, 버튼 묶음)이 줄바꿈한다.
2. 줄어드는 글자는 반드시 **말줄임 + 전체 값**.
3. 내용이 줄바꿈될 수 있는 막대에는 **고정 높이 대신 최소 높이**.

## 점검 도구도 틀린다

2차에서 점검 스크립트의 오탐도 두 개 고쳤습니다.

- 선택창의 화살표 폭을 24px로 가정했더니, 폭이 `auto`라 잘릴 수 없는 선택창을 잘렸다고 보고했습니다. 잠시 `width: auto`로 바꿔 **브라우저가 정한 폭과 비교**하도록 바꿨습니다. 가정값보다 브라우저에게 묻는 쪽이 정확합니다.
- `col-span-full`은 `grid-column-end: -1`이라 `parseInt`로 세면 -1이 됩니다.

그래서 매번 **점검이 살아 있는지** 확인했습니다. 고친 뒤 0건이 나오면, 같은 점검을 고치기 전 버전에 돌려 문제를 잡는지 봅니다. 점검이 아무것도 못 잡아서 0건일 수도 있기 때문입니다.

## 다음 QA를 위해

저장소에 `designQA/` 폴더를 만들어 다음 QA에 그대로 쓰도록 모았습니다.

- **가이드**: 절차(빌드 → 자동 점검 → 점검이 살아 있는지 → 스크린샷 4장 → 기록), 조건, 판정 기준
- **점검표**: QA마다 복사해서 채우는 양식
- **문제 패턴**: 이번에 나온 문제 12가지의 원인과 처방. 새 화면을 만들 때 먼저 읽는 문서
- **기록**: 1·2차에서 본 것과 고친 것
- **자동 점검 스크립트**: 화면에 `data-qa-expand`(펼칠 버튼), `data-qa-grid`(필드 그리드), `data-pin`(고정 열) 표시를 붙이면 다른 화면에도 씁니다

## 배운 것

- **QA 조건은 사용자가 화면을 여는 곳에서 정합니다.** 내가 만든 모니터 폭이 아닙니다.
- **숫자 점검과 눈 점검은 서로를 대신하지 못합니다.** 1차에서는 숫자가 0건인데 화면에서 세로선이 비쳤고, 2차에서는 스크린샷은 멀쩡해 보였는데 숫자로는 수십 건이 나왔습니다.
- **한글 UI에서는 줄바꿈 기본값을 믿지 않습니다.** 한 줄이어야 하는 글자는 명시적으로 막습니다.

남은 일은 하나입니다. 이 환경에는 맑은 고딕이 없어 자간으로 흉내 냈기 때문에, Windows 실제 브라우저에서 한 번은 직접 확인해야 합니다.
